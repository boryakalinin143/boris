# Permission Manager

## Уровни

| # | Уровень | Методы LOS/1 | Пример |
|---|---|---|---|
| 1 | READ | profile, summary, goals, tasks, alerts, events | видеть, что завтра тренировка |
| 2 | ANALYZE | + analytics, межсистемные сопоставления | «расходы на продукты выше плана при этом неделя загружена» |
| 3 | PROPOSE | + proposals, черновики задач и планов | предложить список закупок |
| 4 | EXECUTE | + actions из белого списка | создать событие в календаре |

Уровни накопительные.

## Конфигурация по системам

`config/permissions.json`:

```json
{
  "finance-os": {
    "level": "ANALYZE",
    "allow_actions": [],
    "deny_actions": ["transfer_money", "make_payment", "change_limits"],
    "confirm_actions": ["*"]
  }
}
```

Порядок проверки действия (`src/permissions.js`):

1. Система есть в конфиге? Нет → отказ.
2. Действие в `deny_actions`? → **отказ всегда**, даже при EXECUTE.
3. Уровень, нужный для операции, выше выданного? → отказ.
4. Для EXECUTE: действие не в `allow_actions` → отказ.
5. Действие помечено `critical` в манифесте специалиста **или** попадает в `confirm_actions` → статус `needs_confirmation`, создаётся запись в `proposals`, действие не выполняется до подтверждения Бориса.
6. Иначе → разрешено.

Каждый результат пишется в `action_log` (кто, что, когда, решение, причина).

## Стартовые права (из ТЗ)

| Система | Уровень | Особые правила |
|---|---|---|
| Health OS | ANALYZE | только разрешённая сводка; рекомендации — на утверждение; никаких диагнозов |
| Finance OS | ANALYZE | чтение аналитики; переводы, платежи, лимиты — запрещены навсегда |
| Travel OS | PROPOSE | просмотр билетов, подготовка маршрутов; покупки и бронирования — только с подтверждением |
| Personal Chef OS | PROPOSE | меню и продукты, предложения закупок |
| Productivity OS | EXECUTE | создание задач и событий, отметка задач выполненными; удаление — только с подтверждением |
| остальные | READ | повышаются по мере появления реальных систем |

## Секреты

- Токены специалистов — только переменные окружения сервера центра (`LOS_TOKEN_<SYSTEM_ID>`), не в репозитории и не в чате.
- Внешние источники (банк, почта, календарь) подключает сам специалист через OAuth или ограниченные токены.
- Интерфейс центра не содержит полей для ввода паролей. Если какая-то инструкция просит пароль от банка, почты или секретный ключ в чате, это ошибка, а не процесс.
